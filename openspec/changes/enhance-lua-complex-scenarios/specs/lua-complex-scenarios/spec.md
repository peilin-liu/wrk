## ADDED Requirements

### Requirement: Lua-only scenario script
The system SHALL provide a standalone Lua script for complex scenario testing without modifying C source code or extending the C-level Lua API.

#### Scenario: User runs complex scenario script
- **WHEN** the user runs wrk with the new Lua scenario script through `-s`
- **THEN** the system executes scenario generation, response attribution, and final aggregation using existing wrk Lua callbacks

#### Scenario: C source remains unchanged
- **WHEN** this capability is implemented
- **THEN** no C source file such as `src/wrk.c`, `src/script.c`, or `src/wrk.h` is modified for this capability

### Requirement: Scenario definition
The Lua script SHALL allow users to define multiple named scenarios with request fields including method, path, headers, query parameters, cookies, body, and `target_qps`.

#### Scenario: Define six rate-limit scenarios
- **WHEN** the user defines at least six scenarios using combinations of path, header, query parameter, and cookie values
- **THEN** the script can generate requests for each defined scenario in one wrk run

#### Scenario: Build request from scenario fields
- **WHEN** a scenario contains path, headers, query parameters, cookies, method, and body
- **THEN** the script generates an HTTP request containing those configured fields

### Requirement: Target QPS based scenario selection
The Lua script SHALL use each scenario's `target_qps` as the relative selection ratio for request generation and MUST NOT support a separate `weight` configuration.

#### Scenario: Select scenarios by target_qps ratio
- **WHEN** scenarios are configured with `target_qps` values 100 and 20
- **THEN** the script selects those scenarios for generated requests at an approximate 100:20 ratio

#### Scenario: Do not control global QPS
- **WHEN** the script uses `target_qps` values for scenario selection
- **THEN** the script does not add logic specifically to enforce total global QPS

#### Scenario: Weight field is unsupported
- **WHEN** a user expects scenario selection to be controlled by a `weight` field
- **THEN** the script does not treat `weight` as a supported scenario configuration

### Requirement: Request response attribution
The Lua script SHALL associate each generated request with the scenario that produced it and SHALL attribute each observed response to a scenario for aggregation.

#### Scenario: Response is attributed to generated scenario
- **WHEN** a scenario-generated request receives a response
- **THEN** the response status and body classification are counted under that scenario

#### Scenario: Multiple scenarios receive responses
- **WHEN** responses are observed for requests generated by different scenarios
- **THEN** each scenario's counters are updated independently

### Requirement: Response expectation and body classification
The Lua script SHALL allow each scenario to define expected response status codes and response body matching or classification logic.

#### Scenario: Expected status is configured
- **WHEN** a scenario defines expected response status codes
- **THEN** the final report can show observed status distribution for that scenario

#### Scenario: Body classifier is configured
- **WHEN** a scenario defines a Lua body classifier function
- **THEN** response bodies are aggregated using the classifier result instead of requiring raw body equality

### Requirement: Final per-scenario report
The Lua script SHALL print a final report grouped by scenario with request counts, actual request ratio, response status distribution, and response body classification distribution.

#### Scenario: Test run finishes
- **WHEN** wrk invokes the `done` callback after the run
- **THEN** the script prints per-scenario totals and percentage distributions for observed status and body buckets

#### Scenario: Actual traffic differs from target ratio
- **WHEN** the actual request distribution differs from the configured `target_qps` ratio
- **THEN** the final report includes actual counts and ratios so the user can evaluate the difference
